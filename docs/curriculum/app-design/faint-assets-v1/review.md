# Faint asset presentation preview v1

17 October 2026. **Awaiting explicit user approval. No implementation or hold clearance.**

## Proposal

Use the available content width for original artwork, preserving aspect ratio and a white backing in light/dark themes. For image-choice questions, apply the same enlarged presentation to all four image options whenever any option needs it. This prevents sizing from identifying the intended answer. Candidate starting point: at least 220 dp image height, with enough height for the original aspect ratio at available width; confirm exact dimensions in device proof. Keep deliberate selection/confirmation and existing scroll order. The viewer retains neutral assessment titles, labeled zoom/reset/Close controls, fit at entry and return to the exact trigger. Reference/study contexts use their existing approved captions and full-width artwork areas.

The generated preview is layout-only and uses placement placeholders, following the approved 8J approach. It cannot establish the legibility of S5, S6, S7, S11, S12, S13, T1, T2, T6, T8, T22 or X8. No generated mark is a replacement official asset. The twelve exact bundled/source hashes and all 24 affected question/slot bindings are recorded in asset-bindings.json.

## Approval scope and follow-up

Approval would authorize implementation of this presentation direction, followed by actual-size rendering of the unchanged official bytes on supported targets at light/dark and 100%/160% text. Retain neutral descriptions and selection across zoom, verify scrolling/control reachability and focus return, and inspect each affected stem/option. Enlargement alone may not resolve every faint source stroke; any remaining failed asset stays held. Do not release a question based only on design approval.

The user-provided design workflow requires a preview followed by explicit approval before implementation. No app source, artwork, authored question, eligibility or release decision was changed while preparing this preview.
